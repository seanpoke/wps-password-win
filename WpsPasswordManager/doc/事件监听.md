#### 方案 A：监控“临时锁定文件”（最推荐）

这是针对 Office/WPS 最经典、性能消耗最低的方案。

- **原理：** 当 WPS 打开 `test.docx` 时，同级目录会出现 `~$test.docx`。当这个临时文件被系统**删除**时，说明 WPS 已经彻底关闭了该文档并释放了主文件的句柄。
- **实现：** 使用 `FileSystemWatcher` 监听 `Deleted` 事件，过滤文件名以 `~$` 开头的文件。

#### 方案 B：重试轮询法（基于临时文件）

如果你的后台进程检测到**临时文件**发生了 `Created` 事件（说明 WPS 打开了文档）：

1. 进入一个短时间的轮询循环（例如每 500ms 一次）。
2. 持续检测该临时文件是否存在。
3. 当检测到临时文件被删除时，说明 WPS 已关闭文档并释放主文件句柄。
4. 立即对主文件执行元数据写入操作。

#### 方案 C：利用 Windows 重启管理器 (Restart Manager) API（结合临时文件）

这是一个比较硬核的方案。

- **原理：** 使用 `RmStartSession` 等 API，可以查询特定文件被哪个进程（PID）占用。
- **实现：** 
  1. 监听临时文件的 `Created` 事件，记录对应的主文件路径。
  2. 定期检查主文件的占用者列表。
  3. 当返回的列表为空时，说明 WPS 已经退出了对该文件的占用。
