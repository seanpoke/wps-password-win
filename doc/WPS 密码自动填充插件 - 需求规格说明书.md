## 2.2 设计目标

1. 实现插件核心功能：WPS 加密时密码一键生成 / 填充 / 写元数据、打开时密码读元数据 / 自动填充 / 打开，全程模拟人为操作，无 WPS 内部插件依赖。
2. 完成 Win10+WPS 12.1.0.25225 双基准环境的专属优化，实现该环境下 100% 功能兼容、零异常、最优体验，支持 DPI 缩放、多显示器等 Win10 专属场景。
3. 保证插件无第三方运行环境依赖，编译为独立可执行程序，制作单文件一键安装包，支持零配置使用、企业批量部署。
4. 实现插件对 Windows 7/11、WPS 2019/2021 的向下兼容，确保核心功能全程可用，异常率控制在要求范围内。
5. 保证插件的稳定性、轻量化、易用性，满足企业日常办公的高频率使用需求，资源占用控制在需求范围内。

## 2.3 整体实现方案

### 2.3.1 技术体系选择

插件采用**C# + .NET 6 独立发布**技术体系，核心基于**Windows 系统原生 Win32 API**实现 WPS 进程、对话框、控件的监控与定位，集成成熟的键鼠模拟组件实现人为操作模拟，通过 Open XML 标准实现 WPS docx 文档元数据的读写，采用 WinForm 实现悬浮按钮、系统托盘、轻量提示框等交互元素。

所有依赖组件均采用**源码集成 + 打包**方式，编译时将.NET 运行时、所有核心组件全部打包进单 EXE 文件，实现无第三方环境依赖；最后通过 Inno Setup 制作单文件一键安装包，支持一键安装、静默安装、一键卸载。

### 2.3.2 整体架构分层

插件采用**无主界面的桌面后台程序架构**，整体分为五层，各层级通过事件驱动实现通信，无共享全局数据，耗时操作均在后台异步执行，避免主进程阻塞，保证插件轻量化、高响应。

### 2.3.3 进程与线程设计

插件为**单进程**运行，避免多进程资源占用；内部采用**主线程 + 后台异步子线程**模型，各线程各司其职，按优先级执行，确保核心操作的高响应性。

1. **主线程（UI 线程）**：优先级普通，负责交互展示层所有元素的管理、事件分发，无耗时操作。
2. **WPS 监控线程**：优先级普通，后台循环扫描，负责 WPS 进程、对话框的实时监控，扫描间隔 1s。
3. **控件定位线程**：优先级高，异步执行，接收到对话框识别事件后立即执行控件定位，完成后触发后续业务。
4. **业务处理线程**：优先级普通，异步执行，负责密码生成、元数据读写、异常判断、重试机制。
5. **模拟操作线程**：优先级最高，异步执行，负责密码填充、按钮点击等核心模拟操作，确保无延迟。
6. **日志线程**：优先级最低，异步执行，负责插件运行日志的本地写入，不影响核心业务。

## 2.4 核心功能实现流程

### 2.4.1 加密文档：一键生成填充密码 + 写入元数据

1. 插件启动后，WPS 监控线程后台循环扫描系统进程，检测 WPS.exe 是否运行，同时 Win10 系统信息检测模块完成系统版本、DPI 缩放、显示器数量的检测。
2. 用户在 WPS 中触发「文档加密 / 另存为加密」，弹出密码输入对话框，WPS 监控线程通过系统级 API 识别该对话框，匹配双基准 / 兼容环境特征。
3. 控件定位线程接收到事件后，定位密码输入框、确认密码输入框的屏幕坐标与句柄，Win10 下根据 DPI 缩放比例校准坐标，多显示器下识别对话框所在显示器。
4. 交互展示层根据校准后的坐标，在密码框右侧 5px 位置显示「一键生成密码」悬浮按钮，按钮尺寸、样式匹配当前环境。
5. 用户点击悬浮按钮，核心业务层按规范生成 16 位强密码，暂存于内存（写入元数据后立即释放）。
6. 模拟操作线程接收到密码信息后，模拟人为打字将密码同步填充至「密码」和「确认密码」双输入框。
7. 用户在 WPS 中点击「确定」完成加密，保存文档至本地，插件通过系统级 API 解析文档的本地绝对路径。
8. 核心业务层接收到文档路径后，尝试读取文档并将密码写入自定义元数据，若文档被占用则自动重试 3 次。
9. 元数据写入成功后，内存中的密码立即释放，流程结束；写入失败则触发异常处理，弹出轻量提示框。

### 2.4.2 打开加密文档：自动读取元数据 + 填充密码打开

1. 插件启动后，WPS 监控线程后台循环扫描系统进程，检测 WPS.exe 是否运行，同时完成 Win10 系统信息检测。
2. 用户在 WPS 中双击打开加密 docx 文档，弹出密码解密对话框，WPS 监控线程通过系统级 API 识别该对话框，匹配双基准 / 兼容环境特征。
3. 控件定位线程接收到事件后，定位解密密码输入框、「确定」按钮的屏幕坐标与句柄，Win10 下完成 DPI 缩放和多显示器坐标校准。
4. 插件通过系统级 API 自动解析解密对话框关联的文档本地绝对路径。
5. 核心业务层根据文档路径读取文档自定义元数据中的密码信息，若文档被占用则自动重试 3 次。
6. 若密码读取成功，模拟操作线程先模拟人为打字将密码填充至解密密码框，再模拟鼠标左键点击「确定」按钮，实现文档自动打开。
7. 若密码读取失败，触发异常处理，弹出 3 秒自动关闭的轻量提示框，流程终止，放行用户手动操作。
8. 文档成功打开后，流程结束，所有临时数据立即释放。

## 2.5 关键设计点

### 2.5.1 WPS 控件 / 对话框识别设计

1. **双基准特征固化**：提前通过系统工具抓取 Win10+WPS 12.1.0.25225 双基准环境下，加密 / 解密对话框、密码框、确认密码框、确定按钮的**精准特征**（窗口标题、类名、控件 ID），作为插件默认核心配置，启动时优先加载，直接通过特征精准定位，无需遍历所有控件，提升识别效率和准确率。
2. **兼容特征匹配**：针对兼容环境，配置**模糊特征**（窗口标题关键词、控件类名），通过遍历控件的方式实现识别，保证核心功能可用。
3. **系统 + 版本双匹配**：插件启动后先检测 Windows 系统版本，再检测 WPS 版本，自动匹配对应特征配置，避免版本 / 系统不兼容导致的识别失败。
4. **防误识别**：仅匹配 WPS.exe 进程下的窗口和控件，排除其他程序的同名对话框 / 控件，避免误操作。

### 2.5.2 Win10 系统专属优化设计

1. **DPI 缩放适配**：Win10 下自动检测系统 DPI 缩放比例（100%/125%/150%），对所有控件、悬浮按钮的坐标和尺寸进行等比例校准，确保无偏移、无遮挡，按钮文字清晰无模糊。
2. **多显示器支持**：自动检测系统显示器数量，识别 WPS 对话框所在的显示器，仅在对应显示器的密码框右侧显示悬浮按钮，避免跨显示器定位错误；支持显示器分辨率不一致的场景。
3. **窗口特性适配**：适配 Win10 的 WPS「沉浸式窗口」「贴靠窗口」特性，以及窗口缩放、移动、最大化 / 最小化等操作，悬浮按钮动态跟随密码框，实时刷新坐标，始终保持紧贴右侧。
4. **权限与操作适配**：Win10 下仅需普通管理员权限，适配系统输入防护机制，模拟操作采用 Win10 原生事件，避免被系统拦截；优化模拟操作时序，提升响应速度。

### 2.5.3 悬浮按钮设计

1. **定位规则**：始终在密码输入框**右侧 5px 紧贴位置**显示，左上角坐标为密码框右坐标 + 5px、密码框上坐标，双基准环境下定位偏差≤1px。
2. **样式规则**：无边框、无背景阴影、总在最前；双基准环境下尺寸固化为宽 80px、高 28px，背景色与 WPS 12.1.0.25225 默认主题匹配，字体为微软雅黑、9-12pt（随 DPI 缩放调整）；兼容环境下自适应尺寸，保证视觉协调。
3. **交互规则**：仅鼠标悬停时高亮，点击空白区域 / 关闭对话框后自动隐藏；支持右键点击选择「临时隐藏」，再次识别到密码框时自动恢复；无焦点、不抢占 WPS 操作焦点。

### 2.5.4 强密码生成设计

1. **字符规范**：包含大写字母（A-Z）、小写字母（a-z）、数字（0-9）、特殊符号（!@#$%^&*），四类字符各至少 2 位，总长度 16 位。
2. **随机规则**：采用加密安全的随机数生成算法，避免伪随机导致的密码重复；生成的密码无连续字符、无相似字符（如 1 和 l、0 和 O）。
3. **暂存规则**：密码仅暂存于内存中，元数据写入成功后立即释放，无本地文件、注册表存储，避免密码泄露。

### 2.5.5 文档元数据读写设计

1. **元数据属性规范**：密码写入文档**隐藏式自定义元数据**，属性名固定，用户无法在 WPS 常规属性界面查看，仅插件可识别读取。
2. **格式限制**：仅对 docx 格式文档执行元数据读写操作，通过文件后缀名快速判断，非 docx 格式直接跳过。
3. **重试机制**：检测到文档被占用时，自动重试 3 次，每次间隔 500ms，提升读写成功率。
4. **句柄管理**：元数据读写完成后，立即释放文档文件句柄，避免占用导致 WPS 操作异常。

### 2.5.6 模拟操作时机设计

1. **延迟执行**：识别到对话框 / 控件后，延迟 100ms（双基准）/200ms（兼容）执行后续操作，确保 WPS 控件完全加载，避免因控件未初始化导致的模拟失败。
2. **单次执行**：每个对话框仅触发一次模拟操作，避免重复填充密码、重复点击按钮。
3. **前台优先**：模拟操作前，将 WPS 对话框设为前台活动窗口，确保模拟操作生效，避免因窗口后台导致的操作失效。

## 2.6 分发与部署方案

### 2.6.1 独立 EXE 编译

1. 采用.NET 6 「独立发布」模式编译插件，将.NET 运行时、所有核心组件、源码集成的依赖库全部打包进**单 EXE 文件**，无外部 DLL 依赖。
2. 开启编译优化，移除调试信息、压缩文件体积，确保 EXE 文件大小≤30MB。
3. 编译目标平台为 Windows x64，兼容 Windows 7/10/11（64 位）系统。

### 2.6.2 一键安装包制作

1. 使用 Inno Setup 制作**单文件一键安装包（setup.exe）**，集成独立 EXE、配置文件，实现一键安装、静默安装、一键卸载。
2. **安装流程**：双击安装包→自动校验系统权限→自动选择安装路径（默认 Program Files）→自动创建桌面快捷方式、开始菜单快捷方式→可选开机自启→安装完成，全程无手动配置。
3. **静默安装**：支持命令行静默安装，适配企业批量部署，无任何弹窗、无交互。
4. **卸载流程**：通过开始菜单 / 控制面板 / 桌面快捷方式均可一键卸载，彻底清理安装目录、注册表、快捷方式，无冗余文件残留。
5. **版本检测**：安装包内置**Windows 系统 + WPS 版本双检测**功能，安装时自动识别当前环境，提示用户为「双基准环境（最优体验）」或「兼容环境（核心功能支持）」，无 WPS 则给出温馨提示。

### 2.6.3 分发方式

1. **轻量分发**：安装包为单文件，大小≤30MB，支持企业内网共享、微信 / QQ、U 盘、邮件等多种方式分发，用户双击即可安装。
2. **企业部署**：支持通过企业域策略、桌面管理软件进行批量静默安装，无需人工干预，适配企业规模化部署需求。
3. **离线使用**：插件全程离线运行，无网络依赖，分发后无需后续配置、无需升级，安装后即可永久使用。

## 2.7 异常处理设计

### 2.7.1 异常处理原则

1. **不干扰核心操作**：所有异常处理均不阻塞 WPS 的加密 / 打开流程，仅在必要时进行轻量提示，优先放行用户手动操作。
2. **分层处理**：各层级自行捕获内部异常，通过统一的异常处理模块进行判断，触发对应的处理逻辑，避免异常扩散导致插件崩溃。
3. **零容忍（双基准）**：双基准环境下，针对控件定位、模拟操作、元数据读写三类核心异常，添加**二次重试 + 备用逻辑**，确保功能 100% 生效；重试失败则记录关键日志，轻量提示用户。
4. **低异常（兼容）**：兼容环境下，核心异常率≤0.1%，异常时直接放行用户手动操作，仅记录日志，不进行过度重试。
